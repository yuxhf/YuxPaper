# 网站扩展设计

## 当前首版

当前网站提供框架导览、六层模块探索、阅读阶段切换、文档标题与摘要搜索。所有展示内容都来自随仓库提交的公开框架文字；没有个人论文数据，也没有后台。

## 分阶段落地

### M0：公开框架展示（本次）

无依赖静态页面、文档与教学模板。验收：移动端可读、交互可用、链接可访问、不含私有材料。

### M1：只读公开索引（后续）

在原工作区增加显式导出适配器，从既有 CSV/Markdown 生成允许公开的 JSON。使用 paper_id 连接对象；只导出白名单字段，默认排除本机路径、Zotero 附件路径、私有备注和未公开论断。

验收：同一输入得到相同输出；稳定 ID 不变；所有记录有可解析的来源标识；冲突和缺失记录可见；导出不会修改源文件。导出器本次未实现。

### M2：本地检索与关系浏览（后续）

先实现标题、关键词与全文关键词检索，再评估语义检索是否必要。检索返回来源路径、片段和阅读阶段。公开静态站只搜索已导出数据；私有全文检索在本机服务执行，不向公网暴露文件系统。

验收：检索结果能回到原文位置；图谱边有来源；未读文献不会被当成已核验知识。

### M3：受控编辑（后续，需另行确认）

若需要浏览器编辑，使用本地适配器和受限目录访问。编辑先生成 diff、检查源文件哈希，再写回原文件，冲突时停止。网站不得创建第二套 registry 或 claim ledger。公开多用户服务还需独立设计身份、访问控制、备份与审计。

验收：可预览变更、冲突不覆盖、可恢复、写回路径与既有系统一致。

## 建议的数据接口（设计稿，尚未实现）

- `GET /papers`：公开论文索引与过滤。
- `GET /papers/:paper_id`：来源、状态、获准笔记。
- `GET /concepts`：概念与关联。
- `GET /projects/:project_id/evidence`：获准论断与证据缺口。
- `POST /changes/preview`：仅在未来本地编辑模式生成差异，不直接执行。

这些是后续接口契约建议，不是当前可调用的 API。部署、鉴权与数据库选择应在功能需求明确后决定。

## 技术取舍

当前采用原生 HTML/CSS/JavaScript，适合 GitHub Pages。后续只读数据量较小时继续使用静态 JSON；需要本地编辑或私有全文读取时再加入本地服务。向量库、LLM API 与后台任务不是首版必需项，也未获得本次引入授权。
